Konsep REST API

Memahami arsitektur dan prinsip dasar REST API

REST API (Representational State Transfer Application Programming Interface) adalah gaya arsitektur yang menggunakan protokol HTTP untuk komunikasi antara klien dan server. API ini mengikuti prinsip-prinsip REST yang memungkinkan operasi CRUD (Create, Read, Update, Delete) pada data.

Analogi REST API: Bayangkan REST API sebagai pelayan di restoran. Anda (klien) memberikan pesanan (request) kepada pelayan, pelayan menyampaikannya ke dapur (server), dan kemudian mengembalikan makanan yang dipesan (response).

Keunggulan REST API:

Separasi Frontend & Backend

Memisahkan tampilan aplikasi dari logika bisnis dan database, memungkinkan pengembangan paralel.

Multi-Platform

Dapat diakses dari berbagai platform: web, aplikasi mobile, desktop, atau perangkat IoT.

Skalabilitas

Mudah dikembangkan, diuji, dan dipelihara seiring pertumbuhan aplikasi.

Autentikasi API

Mengamankan akses data dengan API Key

Untuk mengakses API ini, Anda memerlukan API Key yang valid. API Key berfungsi sebagai token otorisasi yang memberikan izin akses ke endpoint yang tersedia.

Langkah 1: Login

Gunakan username dan password yang valid untuk mendapatkan API Key melalui endpoint auth.

Langkah 2: Dapatkan API Key

Sistem akan mengembalikan API Key unik yang berlaku untuk sesi Anda.

Langkah 3: Gunakan API Key

Sertakan API Key di header setiap request ke API untuk otorisasi.

Keamanan API Key: Simpan API Key dengan aman dan jangan bagikan kepada pihak yang tidak berwenang. API Key memberikan akses penuh ke data sistem.

Format Header Request:

Header Request:
GET /api/kelas HTTP/1.1 Host: 103.186.167.18:8000 x-api-key: 140291690063 Content-Type: application/json

GET - Mengambil Data

Membaca data dari server tanpa perubahan

GET http://103.186.167.18:8000/serverapikel5rpl1key/api/kelas

Fungsi: Mengambil seluruh data kelas yang ada dalam database.
Penggunaan: Saat perlu melihat daftar semua kelas yang tersedia di sekolah atau untuk keperluan dropdown selection di aplikasi.

POST - Menambah Data

Menambahkan data baru ke dalam sistem

POST http://103.186.167.18:8000/serverapikel5rpl1key/api/guru

Fungsi: Menambahkan data guru baru ke dalam database.
Penggunaan: Saat sekolah merekrut guru baru yang perlu dimasukkan ke sistem atau ketika ada penambahan staf pengajar.

Testing POST method untuk menambah data guru

Request Body:
{ "id": 5, "nip": 1005, "nama": "Angel", "mapel": "Sejarah" }
Response:
{ "message": "Guru berhasil ditambahkan", "data": { "id": 5, "nip": 1005, "nama": "Angel", "mapel": "Sejarah" } }

PUT - Mengubah Data

Memperbarui data yang sudah ada

PUT http://103.186.167.18:8000/serverapikel5rpl1key/api/siswa/1

Fungsi: Mengubah data siswa yang sudah ada berdasarkan ID.
Penggunaan: Saat ada perubahan data siswa seperti pindah alamat, perubahan nomor telepon, naik kelas, atau koreksi data yang salah.

Testing PUT method untuk mengubah data siswa

Request Body:
{ "nis": "202501", "nama": "Linda Lingling", "jenis_kelamin": "P", "alamat": "Jl. Merpati No.1", "kelas_id": 2, "nama_kelas": "X IPS 1" }
Response:
{ "message": "Data siswa berhasil diperbarui", "data": { "id": 1, "nis": "202501", "nama": "Linda Lingling", "jenis_kelamin": "P", "alamat": "Jl. Merpati No.1", "kelas_id": 2, "nama_kelas": "X IPS 1" } }

DELETE - Menghapus Data

Menghapus data dari sistem secara permanen

DELETE http://103.186.167.18:8000/serverapikel5rpl1key/api/kelas/1

Fungsi: Menghapus data kelas dari database berdasarkan ID.
Penggunaan: Saat kelas tidak digunakan lagi, perlu direstrukturisasi, atau terdapat duplikasi data.

Peringatan: Pastikan tidak ada siswa yang terdaftar di kelas tersebut sebelum menghapus. Operasi DELETE bersifat permanen dan data tidak dapat dikembalikan.

Testing DELETE method untuk menghapus data kelas

Response (200 OK):
{ "message": "Kelas berhasil dihapus" }

Panduan & Tips Penggunaan API

Best practices untuk integrasi yang optimal

Autentikasi

Selalu sertakan API Key di header setiap request. Simpan API Key di environment variable untuk keamanan.

GET untuk Membaca

Gunakan metode GET hanya untuk membaca data. Request GET tidak boleh mengubah data di server.

POST untuk Menambah

Gunakan POST untuk menambahkan data baru. Pastikan data yang dikirim lengkap dan valid.

PUT untuk Mengubah

Gunakan PUT untuk memperbarui data yang sudah ada. Sertakan semua field, bukan hanya yang berubah.

Hati-hati dengan DELETE

Operasi DELETE bersifat permanen. Implementasikan konfirmasi sebelum menghapus data.

Response Codes

Periksa kode response: 200 (sukses), 400 (client error), 401 (unauthorized), 500 (server error).

Validasi Data

Validasi data sebelum mengirim request. Pastikan tipe data dan format sesuai dengan dokumentasi.

Error Handling

Implementasikan error handling yang baik pada aplikasi client untuk menangani berbagai skenario.
